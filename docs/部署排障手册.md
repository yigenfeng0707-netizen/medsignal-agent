# MedSignal 部署排障手册

> 适用对象：负责把 MedSignal 发布到魔搭创空间（`gsym236998/medsignal-demo`）或本地 Docker 的维护者。
> 本文只讲「出问题怎么查、怎么修」；首次部署流程见 [魔搭创空间部署指南](魔搭创空间部署指南.md)，变量清单见 [部署配置清单](部署配置清单.md)。

## 0. 30 秒定位法

任何「线上不对」的问题，先按这三步取三份证据，再动手：

| 顺序 | 证据 | 命令 | 判读 |
|---|---|---|---|
| 1 | 创空间是否在跑 | `GET /openapi/v1/studios/{owner}/{repo}` | `Building/Deploying` = 还在构建，**别急着改代码**；`Running` = 容器已起 |
| 2 | 服务与依赖是否健康 | `GET https://<owner>-<repo>.ms.show/api/health/detailed` | 看 `llm.available`、`knowledge_base.chunks`、`demo_mode` |
| 3 | GitHub 侧是否成功 | `gh run list --limit 3` | `Deploy to ModelScope` 失败 → 看日志；成功但线上旧 → 见第 2.3 节 |

三份证据互相对照，能立刻把问题归到「没构建完 / 构建失败 / 环境变量没同步 / 代码没推上去 / 前端缓存」其中一类，避免盲目重试。

### 取令牌（所有 OpenAPI 调用的前提）

```python
import pickle, os
jar = pickle.load(open(os.path.expanduser("~/.modelscope/credentials/cookies"), "rb"))
tok = [c.value for c in jar if c.name == "m_session_id"][0]
```

- OpenAPI 必须带浏览器 UA：`User-Agent: Mozilla/5.0 ...`，否则会被拦。
- `cookies` 里的 `m_session_id` 是 OpenAPI 令牌；`git_token` 只对 git 推送有效，拿它调 OpenAPI 会 401。
- 令牌绝不提交到仓库，只放 GitHub Secrets。

## 1. 症状速查表

| 现象 | 最可能原因 | 跳到 |
|---|---|---|
| 公网 403 / 空响应 | CDN 拦截非浏览器 UA | 3.1 |
| 页面能开，接口全 404 | 前端把 API 指到了错误域名，或后端未挂载路由 | 3.2 |

| Actions 卡在 `Docker Build Verify` | 镜像构建慢（torch/chromadb），非故障 | 2.6 |

## 2. GitHub Actions 与创空间侧

### 2.1 部署工作流失败

`Deploy to ModelScope` 的四个步骤按顺序卡点定位：

1. **Assemble deploy package** 失败 → 通常是 `rsync` 的排除规则把必要文件排掉了（`pnpm-lock.yaml` 必须保留，`Dockerfile` 用 frozen-lockfile）。
2. **Push to ModelScope Space** 失败 → 先看是不是 `[rejected]`：远程 `master` 有新提交没合并。工作流内置 3 次 fetch 重试 + `merge --allow-unrelated-histories -X ours`，连续失败说明网络到 `www.modelscope.cn` 不通，或令牌失效。
3. **Sync secrets/variables** 出现 `::warning::... 同步失败` → 看同一步打印的 HTTP 码；401 = 令牌问题，404 = 创空间名/owner 拼错。
4. **Trigger Studio build** 非 200 → deploy API 拒绝，通常是创空间正处于 Building 状态，等它跑完再触发。

```bash
gh run view <run-id> --log-failed        # 只看失败步骤日志
```

### 2.2 构建阶段长时间停在 Building

先看构建日志，不要猜：

```bash
gh workflow run modelscope-logs.yml      # 拉取 build/run 日志
```

或用 OpenAPI 直接查 `.../logs/build`、`.../logs/run`。

常见原因：Dockerfile 里 `pip install` 拉取超时（容器网络波动）、`chroma_data` 体积过大被打进镜像（应由 entrypoint 在挂载点重建）、requirements 版本冲突。

本次实测的时序可作参考（2026-11-03）：`Building ≈ 6 分钟` → `Deploying ≈ 1.5 分钟` → `Running`。明显超过 15 分钟才有问题。

### 2.3 部署成功但线上还是旧版本

这是本仓库踩过最多次的坑（2026-08-24 实测：连续两次 git push 均未触发重建，线上仍跑旧镜像）。

**处置**：显式调 deploy API，不要依赖 git push 自动构建。

```python
requests.post(f"https://modelscope.cn/openapi/v1/studios/{owner}/{repo}/deploy",
              headers={"Authorization": f"Bearer {tok}", "User-Agent": "Mozilla/5.0"}, timeout=30)
# 200 且 data.status == "Building" 才算触发成功
```

**判据必须用特征字段，不能只看 200**：

| 特征字段 | 位置 | 说明 |
|---|---|---|
| `llm.primary_model` | `/api/health/detailed` | 与本次配置一致才算新镜像 |
| `knowledge_base.chunks` | `/api/health/detailed` | 政策库扩容后应从 ~150 涨到 241 |
| `/_next/static/chunks/app/<page>-<hash>.js` | 首页 HTML | hash 变化说明前端产物更新 |
| 业务行为 | 如 `POST /api/policy/search` 带 `region` | 旧版无此字段，返回体会缺 `region` |

另外注意：**README 等文档改动不会触发部署**。部署工作流只监听 `backend/**`、`frontend/**`、`deploy/modelscope/**`、`data/**` 和 workflow 文件本身；仅改文档时线上保持原样是预期行为。

### 2.4 环境变量不生效

创空间容器环境变量的真实来源是**平台侧保存的 secrets/variables**，不是仓库里的 `ms_deploy.json`。改 `ms_deploy.json` 后 push，容器仍会用旧值（2026-08-27 排查记录：曾因平台侧 `LLM_API_KEY` 残留失效旧值导致 chat 504）。

处置：通过 OpenAPI 显式 upsert：

```bash
# 存在则 PUT，不存在则 POST
curl -s -X POST "https://modelscope.cn/openapi/v1/studios/$OWNER/$REPO/variables" \
  -H "Authorization: Bearer $TOK" -H "Content-Type: application/json" \
  -d '{"key":"LLM_BASE_URL","value":"https://ainfra.lynxicloud.com/v1"}'
```

> 提示：写完后必须重新触发一次构建/重启，变量才会进容器。

### 2.5 免费实例休眠

免费 2vCPU/16G 实例长时间无访问会休眠，表现为首屏转圈 20–60 秒或直接超时。

- 检查保活工作流是否在跑：`gh run list --workflow keepalive.yml --limit 3`。
- 保活为 `*/5` cron，每分钟 5 次探测会产生大量 run，工作流自带「删除 1 天前 run」的自清理逻辑；若发现 Actions 列表被刷爆，检查 `permissions: actions: write` 是否还在。
- 冷启动慢时不要误判为故障，先等 60 秒再复测。

### 2.6 CI 卡在 Docker Build Verify

`CI` 工作流的第三个 job 会实际构建后端镜像（含 torch、chromadb 等重依赖），单次 15–30 分钟属正常；它只做「镜像可构建」校验，与线上部署互不影响。

判断标准：`Backend Lint & Test`、`Frontend Lint & Build` 两个 job 绿了，就说明代码质量门禁已过。

## 3. 线上功能侧

### 3.1 公网 403 或空响应

CDN 会拦截 curl / requests 的默认 UA。所有探测都要带浏览器 UA：

```bash
curl -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36" https://<owner>-<repo>.ms.show/api/health
```

### 3.2 页面能开但接口全 404

前端必须走**同源相对路径** `/api/...`，禁止把外部后端域名烘焙进构建产物（旧域名失效会导致每次请求先超时再降级，表现为「页面很慢但最终能用」）。

核查方式：下载首页 HTML，取出 `_next/static/chunks/*.js`，搜索是否残留旧域名。

### 3.3 `/api/health` 返回 404 或返回 index.html

FastAPI 的 SPA 兜底路由必须**最后注册**，显式路由（含 `/api/health`）定义在它之前；否则所有路径都会被拿去返回 `index.html`。

### 3.4 回答变成固定模板 / 明显不是模型生成

按三级降级链逐层排除：

1. `DEMO_OFFLINE=true`？后端会主动跳过 LLM 与知识库初始化，即使配了 Key 也不调用。线上应为 `false`。
2. `/api/health/detailed` 看 `llm.available`。`false` 说明主力客户端没初始化起来（Key 为空、占位符、base_url 错）。
3. `llm.available=true` 但请求超时 → 主力端点不可达，看 `fallback_model` 是否接管。
4. 端点凭据过期：类脑云凭据有有效期（当前批次至 2026-11-06），过期后自动回落 DashScope `qwen-plus`，服务不挂但 `primary_model` 会变。

自行验证端点可用性（不经后端）：

```bash
curl -s https://ainfra.lynxicloud.com/v1/models -H "Authorization: Bearer $KEY"
curl -s https://ainfra.lynxicloud.com/v1/chat/completions -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"Qwen3_8B","messages":[{"role":"user","content":"高血压注意什么"}],"max_tokens":40}'
```
返回里的 `performance` 字段含 `ttft`、`tpot`、`total_tps`，可直接判断时延是否正常。

### 3.5 政策检索条数偏少 / 地区不对

- `knowledge_base.chunks` 明显低于预期（当前 30 篇政策应为 241 个 chunk）→ 索引没重建。本地执行 `python scripts/build_knowledge_base.py` 后重新部署。
- 检索结果只有某一省 → 检查请求是否带 `region`，以及 `policy_matcher.REGION_COMMON` 是否仍包含「国家」「长三角」。
- 索引必须落在持久化挂载点 `/mnt/workspace/chroma_data`，否则容器重启即丢，触发重建 + 模型重下（表现为启动特别慢）。

### 3.6 轮询状态时偶发 SSL 断连

本机长时间轮询 OpenAPI 会偶发 `SSLEOFError: UNEXPECTED_EOF_WHILE_READING`。属于瞬时网络问题，**不是服务异常**，加重试即可：

```python
for attempt in range(3):
    try:
        r = s.get(url, headers=h, timeout=20); break
    except Exception:
        time.sleep(5)
```

## 4. 本地环境

| 现象 | 原因 | 处置 |
|---|---|---|
| `git commit` 报 `ParserError` | PowerShell 不支持 heredoc | 把提交信息写入临时文件后 `git commit -F <file>` |
| `git push` 报 Connection reset | HTTPS 出站被阻断 | 仓库已用 `ssh://git@ssh.github.com:443` 走 443 端口，保持即可 |
| `ms whoami` 报 `Missing API token` | 本机未设 `MODELSCOPE_API_TOKEN` | 不影响 git push 与 Actions（Actions 用 Secrets）；仅 CLI 命令受影响 |
| 本地启动后政策库为空 | 未构建 Chroma 索引 | `python scripts/build_knowledge_base.py` |
| `backend/chroma_data/` 出现在 git 状态里 | 索引不应入库 | 已在 `.gitignore` 排除；索引由脚本重建 |

---

## 5. 回滚

1. **代码级**：`git revert <commit>` → push → 自动触发部署（改动落在 `backend/**` 等监听路径内时）。
2. **配置级**：只需回退模型/端点，改 OpenAPI variables 后重新触发部署，不必回退代码。
3. **应急**：把 `DEMO_OFFLINE` 置为 `true` 重新部署，跳过 LLM 与知识库初始化，全功能走本地引擎与 mock，保证演示不中断。
