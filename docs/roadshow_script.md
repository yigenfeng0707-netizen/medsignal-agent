## 0:30–1:30 问题定义 — Problem Statement

我们来看三组数据：

**第一，咨询量巨大。** 浙江省有5600万参保人，人均每年咨询医保问题3.2次。这意味着每年有超过1.8亿次的医保咨询需求，而全省医保经办窗口只有不到5千个。供需严重失衡。

**第二，政策看不懂。** 一份医保政策文件平均阅读时长47分钟，充斥着"统筹基金""起付标准""乙类先自付"这样的专业术语。普通参保人根本看不懂，更别提58岁的张阿姨了。

**第三，红利不知道。** 80%的参保人不知道自己可以享受哪些政策红利。比如张阿姨，她连续3个月购买降糖药物，完全符合门诊慢病待遇的申请条件——但她不知道。如果申请成功，她每月的药费可以从自付240元降到自付72元，**一年能省2016元**。

这三个问题的本质是什么？是**信息不对称**。政策在文件里，权益在系统里，但参保人和它们之间，隔着一堵看不见的墙。

## 5:00–6:30 技术亮点 — Technical Highlights

刚才的演示背后，是四个核心技术亮点：

### 1. Multi-Agent 多智能体架构

我们设计了5个专业智能体加1个编排智能体：

- **权益管家**：负责医保权益查询与测算
- **报销助手**：负责OCR票据识别与报销预审
- **健康卫士**：负责健康画像与风险预警——这是我们的核心创新
- **政策参谋**：负责政策精准匹配与省钱计算
- **安全守门**：负责数据授权与合规审计

编排智能体负责意图识别和路由分发，支持单一意图、复合意图、依赖意图三种协作模式。用户不需要知道该找谁，说一句话，系统自动调度。

### 2. 可信数据空间对齐

我们的架构完全对齐浙江省医保数据要素战略的"1+3+N"技术框架：

- **1个数据底座**：统一数据治理
- **3个核心能力**：隐私计算（可用不可见）、区块链存证（可信可追溯）、数据沙箱（可控可计量）
- **N个应用场景**：我们的健康画像、政策匹配就是典型场景

医保数据要素已被国家数据局列为重点示范领域。**我们不是在造空中楼阁，我们是站在省级战略的肩膀上。**

### 3. 从"事后报销"到"事前预防"的健康预警创新

这是医保智脑最核心的差异化价值。传统医保系统是"你生病了来找报销"，我们是"你的数据告诉我你可能出问题了，我来提醒你"。通过分析用药记录、就医频率、购药间隔等数据模式，主动发现健康风险，推送分级预警。

### 4. 全链路可解释性

每一个决策都有来源。报销计算有公式推导，政策推荐有原文引用，健康预警有数据证据。**我们不做黑箱AI，我们做的是参保人能看懂、能信任的AI。**

## 附录：Q&A 准备

### Q1："数据安全怎么保证？"

**建议回答**：

数据安全是我们的底线，从三个层面保障：

第一，**架构层面**，我们有专门的安全守门智能体，任何数据访问都必须经过授权验证，没有授权一律拒绝。授权分四级，敏感数据需要每次单独确认。

第二，**技术层面**，我们完全对齐浙江省医保数据要素战略的"可用不可见、可控可计量、可信可追溯"三大原则，采用隐私计算、区块链存证、数据沙箱等技术。

第三，**合规层面**，严格遵守《个人信息保护法》和《数据安全法》，医疗健康数据属于敏感个人信息，处理需取得单独同意，支持随时撤回。所有数据访问都有完整的审计日志。

### Q2："和现有'医小保'有什么区别？"

**建议回答**：

医小保是优秀的政策咨询工具，但它本质上是"被动问答"——你问什么，它答什么。医保智脑有三个本质区别：

第一，**主动预警**。医小保不会告诉你"你该去复查了"，医保智脑会。我们的健康卫士智能体会主动分析你的数据模式，推送风险预警。

第二，**多智能体协作**。医小保是单一模型，医保智脑是5个专业智能体+编排器，每个智能体有独立的专业知识和交互规则，协作处理复杂问题。

第三，**全链路可解释**。我们的每个决策都有政策原文引用和计算推导过程，不是黑箱输出，参保人能看懂、能信任。

### Q3："商业模式是什么？"

**建议回答**：

三层模式：

**To G**：为医保部门提供智能客服能力，替代部分人工窗口。按调用量或按年服务费收费。一个省级医保部门每年在咨询热线和窗口的人力成本超过2亿元，我们的系统可以降低30%-50%的重复咨询量。

**To B**：基于可信数据空间，为商业保险公司提供数据赋能服务，支撑精准定价和快速理赔；为药企提供真实世界数据分析。这是数据要素变现的核心路径。

**To C**：基础权益查询免费，健康管理增值服务收费。比如个性化健康方案、慢病管理跟踪、体检提醒等。参考互联网医疗平台的付费会员模式。

### Q4："3天做的能落地吗？"

**建议回答**：

3天做的是核心架构和关键场景的MVP验证。我们的落地路径分三步：

**第一步（1-3个月）**：接入浙江省医保数据赋能实验室的沙箱环境，用脱敏数据完成核心功能验证，与医保部门联合测试。

**第二步（3-6个月）**：选择1-2个区县进行试点，覆盖5-10万参保人，收集真实用户反馈，迭代优化。

**第三步（6-12个月）**：基于试点数据，向全省推广。浙江省已有医保数据要素战略的基础设施支撑，规模化部署的技术障碍不大。

关键是我们站在了省级战略的肩膀上——医保数据要素基础设施持续完善，数据赋能实验室已经启用，我们不需要从零搭建基础设施。

### Q5："健康预警的准确率如何？"

**建议回答**：

首先需要明确，我们的健康预警不是医疗诊断，而是**基于数据模式的风险提示**。我们的定位是"提醒你该关注了"，而不是"告诉你得了什么病"。

准确率从两个维度衡量：

**召回率（不漏报）**：我们的规则覆盖了慢病管理风险、重复用药、就医频率异常、用药间隔异常四大类场景，基于临床指南和医保数据特征设计，确保高风险情况不被遗漏。

**精确率（不误报）**：每条预警都附带数据证据和推理过程，用户可以自行判断。同时我们设置了三级预警等级——高风险建议48小时内就诊，中风险建议1-2周内复诊，低风险仅作提醒——避免过度预警导致"狼来了"效应。

随着数据量增加和模型迭代，准确率会持续提升。初期我们会偏重召回率，宁可多提醒，也不漏掉真正的风险。
