# 医保智脑 · 冠军级升级改造计划 v2.0

> 目标：**稳拿一等奖 + 冲击全场最高分 + 代码可落地交付医保局试点**
> 范围：全套升级（P0 接线修复 → P1 核心算法 → P2 创新亮点 → P3 工程化/测试/演示保障）
> 基线：前端 90% / 后端 Services 80% / 后端 Router 20% / AI 实际生效 15% / 安全鉴权 0% / 测试 0%
> 完成后目标：前端 98% / 后端 Router 95% / AI 实际生效 95% / 安全鉴权 70% / 测试 60% / 创新亮点 +3

---

## 诊断结论速览（为什么必须升级）

| 致命问题 | 根因位置 | 影响 | 评委追问即翻车 |
|---|---|---|---|
| AI 链路被旁路 | `routers/agents.py:104-113` mock 优先 return | 386行编排器+422行LLM+642行RAG 全失效 | "这是真AI吗？" |
| 数据库形同虚设 | 6 个 Router 零处 `Depends(get_db)` | 10 用户数据已入库却从不查询，永远只演示张阿姨 | "换个用户看看" |
| 核心算法是空壳 | claims/health/policy 全硬编码 | 报销永远 253.5 元，健康分永远 72 | "改个输入看真实计算" |
| 零鉴权 | 全后端无任何 auth，CORS `*` | "安全守门 Agent" 名不副实 | "你的安全Agent呢？" |
| 前后端契约不一致 | api.ts `payment_history:number[]` vs Router 返回对象数组 | 后端真实数据接通后前端渲染可能崩 | 现场翻车 |
| 0 测试 | 无任何 pytest/vitest | 改一处怕崩全局，不敢现场演示调试 | 稳定性存疑 |

## 🔴 阶段 P0 — 接线修复（让真货生效）

### P0-1 激活 AI 对话链路
- 删除 `agents.py:104-113` 的 mock 优先 return 逻辑
- 改为先走 `orchestrator.route_to_agent()`，mock 仅作 orchestrator 兜底
- 把数据库真实用户画像作为上下文注入 orchestrator

### P0-2 打通数据库查询层
- 新增 `backend/app/crud.py` 统一数据访问层
- 6 个 Router 全部注入 `Depends(get_db)` 查询真实数据

### P0-3 修复前后端数据契约
- 前端 `CoverageSummary.payment_history: number[]` → `PaymentRecord[]`
- 统一 `Activity` 字段命名
- 编写 `docs/api_contract.md`

### P0-4 修正 embedding 模型配置
- 改用 ChromaDB 默认 `sentence-transformers` 离线嵌入（无网络依赖）

## 🟡 阶段 P1 — 核心业务算法落地

### P1-1 报销计算引擎（claims_engine.py）
逐步推导：费用分类 → 乙类先自付 → 起付线 → 报销比例 → 封顶线 → 大病保险
配套 `data/reimbursement_rules.json` 报销规则库

### P1-2 健康风险评分算法（health_engine.py）
5 维评分模型 + 预警规则引擎，每条预警带 evidence 数据证据

### P1-3 政策精准匹配算法（policy_matcher.py）
用户画像 → 政策特征向量 → 规则匹配+向量相似度双轨打分 → 省钱计算

### P1-4 报销测算增强
复用 claims_engine，支持多场景对比（社区医院 vs 三甲）
